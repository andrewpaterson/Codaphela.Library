D. Performance
--------------
D1. [275] An object's stack froms are a tail-appended list (SetLastNext → FindLast), and HasStackFroms counts the whole list: every Ptr copy to a widely held object is O(n). Head insertion and a non-NULL test would do.  [done c7fc65b61]
D2. [341] CDependentWriteObjects::GetUnwritten scans round from the last position each call: O(n²) over a write.  [done 47f0b4ac0]
D3. [433] DeflateLengthCode / DeflateDistanceCode scan their tables on every call (3–4 calls per match); use lookup tables.  [done 41b4355f7]
D4. [443] TextDiffLineMapper::TransferLine scans every block in float64 (soft float on the W65C816).  [done 8246dfa29]
D5. [444] MyersDiff::Bisect resizes and refills both V arrays per range.  [done 7472ff16f]
D6. [452] CMemberCalls::Call copies the array and re-checks Contains per call: O(n²).  [done b7c77ae81]
D7. [297] CRoot::Get(name) scans every root object with strcmp (CObjects has a name index).  [done d97f58794]
D8. [272] CKillOrderCalculator restarts its scan after each pick: O(n²) (fine while n is small).  [done 51cda2842]
D9. [386] ValidateInternalConsistency's check is needed (a stack pointer inside an object is a Ptr field missing from its Class()), but it walks every stack pointer for each object: O(objects × stack pointers).  If validation with many live stack pointers is ever slow, one sorted pass finds the same: the stack pointers' addresses sorted once and each object's range binary searched.  Low priority: it only runs in validation and stack pointers are usually few.  [done 461d75cce]
