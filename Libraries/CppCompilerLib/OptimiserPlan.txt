CppCompilerLib: the IR and the optimiser, put right
===================================================

A plan for findings 60 to 74 and 97 of SmellCheckFindings.txt: the IR layer and the optimiser, where each pass works
out for itself what the others also work out.  Written 2026-11-21.  ConsolidationPlan.txt left the IR layer "to the
sessions working in them"; the user gave it to this plan that day.  The findings say where each thing is and what
the clean form would be, and are not repeated here.

Where it is: stages 0 to 8 are done (2026-11-22).  Stage 9 is next; "The record", at the end, has what each stage
found.


The rules (the user, 2026-11-21)

  1. The code the compiler writes may change (ConsolidationPlan's rule: it must work, and ideally is faster).  The
     bar for a stage that changes it: every program of the three *65 suites still passes on both processors, and no
     suite's total of cycles or of bytes is worse on either.  A stage that only moves code about (marked "same
     code" below) must leave every unit's listing as it was.
  2. The IR layer is this plan's to change.
  3. All of the findings, with the IR parser's move onto BaseLib's CTextParser (74) last.
  4. A stage is merged to master when it has passed.  The work is done in D:\gameengine-optimiser (branch
     ir-optimiser).
  5. Plan first; measure before and after.


How a stage is proved

  - TestCppCompilerLib whole (RunParallel.py).  TestIR.cpp is the optimiser's own: a stage that makes one helper of
    several gives the helper its own cases there.
  - "Same code": each of the three *65 suites' projects compiled for each processor a unit at a time with the
    listings kept (TEST_PROJECT65_LISTINGS, TEST_PROJECT65_ONLY=NoSuchTest, TEST_PROJECT65_SERIAL=1), and the 4,201
    listings compared with the stage before's.
  - Otherwise: the three suites run on both processors (Tests/CompilerMeasure.py --raw), every program's cycles and
    bytes set beside the stage before's, from the same folder (a program's size depends on its sources' paths).
    What moved, and why, goes in the record.
  - The compiler's own time and counts for TestSupportLib65's project (CompilerMeasure.py --compile --serial):
    the optimise phase, optimised functions and optimiser rounds, and each pass's runs and time.  A stage that
    makes one analysis of three must not make the optimiser slower without saying so.
  - The machine has 7.9 GB: a *65 suite and TestCppCompilerLib are never run at the same time.


The stages

Each names its findings.  The order is: the tests that are missing, then what only moves code about, then the
helpers the passes share, then the analyses, then the parser.

0. The baseline, and the tests the IR's parser and verifier lack (97).

   - The measures above, taken at the plan's commit and kept (the record).
   - TestIRParserErrors and TestIRVerifierErrors exist and give each some wrong IR; 14 of the parser's diagnostics
     and 18 of the verifier's are raised by no test (appendix A of SmellCheckFindings.txt).  Each gets a case, with
     its text asserted.  One that cannot be raised from any text is said to be so here, and why.
   - Finding 97 said there were no such tests; that was too much, and is put right in the findings file.

1. An opcode's facts are in the opcode table (62).  Same code.

   The table gets what the passes keep for themselves: an accessor for a comparison's uiHolds; columns for an
   opcode's unsigned twin and its divide/remainder twin; and class bits (integer arithmetic, divide, extension,
   signed wrapping) that the hand lists become tests of (IROptimiserHoistable, IRSpecialiseFollows,
   IROptimiserNarrows, IsIRSignedWrapping, IsIRIntegerConversion).  Gone: gaiIRRelations and gaiIRSignedness, the
   two ternaries that are IRInvertedComparison and IRSwappedComparison again, "uiOpcode += IRO_ULt - IRO_SLt",
   IRKnownBits' two switches.  Where two lists differ, each difference is looked at: kept as a named class if it
   is meant, and noted in the record if it was an accident (then the stage is not "same code" for that pass).
   TestIRComparisonColumns grows to the new columns.

2. One row for each pass (67).  Same code.

   A table: the pass's enum, name, group, function and one line of what it does.  gaszIRPasses, InitPasses and the
   documentation come from it; the enum's comment says what is true.  ConstantDivisions is said once for each
   target (ShareDivisions asks the pipeline, by CIRPipeline::Has, which then has a caller).  IR.txt's list of
   passes is made the table's.

3. A symbol's attributes are one set (70).

   One bit set for restrict, local, regcall, nowrites and nothrow with a {bit, keyword} table: one parse, one print
   loop, one CopySymbolAttributes for IRImports and IRInliner.  Same code, but for this: the two copies carry
   neither nowrites nor local today.  Whether carrying them is right is looked at first (a test of what an
   imported function's caller may assume); if it is, they are carried and the code may get better.

4. Instructions are built by the builder (72).  Same code.

   CIRFunction::Add and CIRPasses::InsertInstruction take the source line, and the five places that build an
   instruction field by field use them (two of them skip the memset today).  The passes use
   CIRDefinitions::IsDefinedBy where they write it out.

5. What a branch says on an edge, and a loop's test (61).

   One edge-condition helper (the compare, the opcode as it holds on the edge, the value on the left) and one
   loop-test record (the block, the compare as it holds going round, the targets inside and outside).
   EdgeComparison is the form to start from.  EdgeBound, UnsignedMaximum, LoopGuarded, GuardedBy, EntryRelations
   and the loop tests of Loops, Counters and Idioms ask it.  LoopGuarded and GuardedBy differ in how far up they
   look (16 dominators against the nearest branch): the reach becomes a parameter, and each caller keeps its own.

6. A loop's counters are found once (60).

   The loops analysis finds each loop's induction variables (the phi, where it starts, its step, the value that
   comes round, the block it comes round from), and one helper gives the value after n times round.
   MatchCounter, ReduceStrength's own, ReplaceLoopCounters' second counter, MatchIdiomStep, MatchLinear, the
   pointer phi of MatchIdiomAddress, ReplaceStrchr's and ReplaceExitValues' ask it.  Each copy accepts its own
   steps today (add only; add or sub; ptradd): each caller says which it takes, so a stage that makes them one
   does not by itself make a pass take more.  Taking more is then a line in a caller, measured on its own.

7. Loop set-up and the three Reduce passes (65).

   One walk "for each simple loop and each of its counters" for ReduceDivisions, ReduceStrength and
   ReduceMultiplies; Preheader(uiLoop), which makes one when it is needed, for the three forms of "get the
   preheader"; AddCounterPhi for the stepped phi built three times.  CounterUnwrapped takes the counter, not its
   four parts.

8. One copier of blocks (66).

   A block copier that takes a value map and a block map, with a hook for what a return becomes: the inliner's
   CopyBlock, UnswitchLoops' own (and CopyHead) and CIRFunction::CopyBody.  One switch rebuilds a jump.

9. The library idioms (64).

   One matcher that gives the loop's shape (head, latch, the two exits, the loads, the compare as taken) and a
   table of idioms (name, 32 bit name, kinds of argument).  ReplaceLoopIdioms' ladder of names reads the table.
   The phis of the exit, the widened byte and the IR_IDIOM_MIN_BYTES test are each written once.

10. Division by a constant (71).

   A matcher that gives an SIRConstantDivision (signed, remainder, divisor); the reciprocal a struct kept in the
   found record, so FindReciprocal runs once; SIRBoundDivision's two flags a kind.  The quotient is a copy, not
   "add q, 0", if every back end takes it as well (measured).

11. One analysis of how big a value can be (63), asked without modes (68).

   An SIRRange (unsigned and signed bounds), one transfer function for each opcode, one refinement on an edge
   (stage 5's helper), kept in the pass context and asked by the passes and by the 65C64's back end
   (CIRKnownBits::FitsType's two callers).  InstructionMost, UpperBound and SignedRange become it; a range is a
   struct, not two int64 pointers through ten functions.  What to narrow by (branches, dominators) is a parameter
   of the question, not two members set before it and cleared after.  The three know different opcodes today, so
   this stage changes the code: it is the one most likely to, and is measured pass by pass.

12. The pass groups (69).

   What edits the flow graph (AddPreheader, RedirectJump, RemovePhiArguments) goes on CIRFunction or CIRLoops;
   addresses (SplitAddress, IsOwnFrame, IsFrameRoot, with their two bare limits named) become an analysis class
   in the context beside the ranges; a temporary's uses are counted once (CIRDefinitions::NumUses or mauiUses,
   whichever the passes can keep right as they replace).  OnlyUsedInLoop takes the uses to leave out, where
   Idioms decrements mauiUses and puts it back.  CIRPassContext's fields the groups no longer need are private.

13. The summaries between functions (73).

   One "optimistic summary" helper (mark every function, take back until nothing changes) with the test as a
   callback, for MarkNoWrites and MarkNoThrow.  CIRModule::MayThrow moves beside the interprocedural code and
   walks reachable blocks by a shared walker; IRReplaceUses uses CIRPasses' walk of uses.

14. The IR's parser on CTextParser (74), and what is left.

   IRParser.cpp's scanning (about 360 lines) is BaseLib's CTextParser, with a configuration for the IR's comments
   and names; the top level's ladder of keywords is a table.  Stage 0's parser tests are what say it reads the
   same.  The stale comment in IROptimiserInternal.h.  Then the findings file gets a "Since:" for each of 60 to
   74 and 97, and this plan its last table.

Stage 3: a symbol's attributes are one set.

	SIRSymbolDefinition has uiAttributes (IRSA_Restrict, Local, RegisterCall, NoWrites, NoThrow) where it had
	five bools; CIRModule has SetSymbolAttributes, GetSymbolAttributes and CopySymbolAttributes, and the ten
	setters and askers named for one attribute are each a line over them.  The restricts are counted in the
	one setter.  gasIRSymbolAttributeNames is the four that are written ("restrict @name"), in the order they
	are printed: the parser's four functions are ParseSymbolAttribute and its ladder of keywords a loop over
	the table, and the printer's four loops are one.  IRImports and IRInliner each carried restrict, regcall and
	nothrow to another module by hand: both call CopySymbolAttributes with IRSA_Carried, which is those three.
	TestIRSymbolAttributes has the set, the count, the copy and the printed order.

	Not carried, as before: local, which must not be (another unit's symbol of the name is another thing), and
	nowrites.  Carrying nowrites would be sound (it is a proof about the function's definition, and a function
	has one), and would let a unit that inlines another's function keep what it knows of memory across the
	calls that function makes; it changes the code, so it is not in a "same code" stage.  It is one line
	(IRSA_Carried) and three suites to measure, and is left for the user to ask for.

Stage 5 (2026-11-21): what a branch says on an edge, and the ways of a loop's branch.  Same code: the 4,201
listings are the baseline's.  TestCppCompilerLib passes (271,441).

	SIREdgeCondition (IRBlock.h) is what a block's branch says on one of its two ways out: the integer comparison
	it is on, as it holds going that way, with its operands.  It is written with a given value on the left
	(PutLeft, swapping if it must) and with a greater than or a less or equal turned round (Unswap), so two
	that say one thing read the same.  CIRPasses::EdgeCondition makes one for an edge.  TestIREdgeCondition has
	each of those.

	What asked a branch the same thing for itself and now asks it: CIRRangePasses::EdgeComparison (which the
	range passes go on calling), CIRKnownBits::EdgeBound, CIRCounterPasses::LoopGuarded and UnsignedMaximum,
	CIRIdiomPasses::GuardedBy and CIRFoldingPasses::EntryRelations; and of the idiom matchers'
	loops, MatchIdiomCounter's latch, ReplaceStrlen's "round while the byte is not 0", ReplaceMemcmp's "on while
	the two are the same" and ReplaceMemchr's "out when the byte is the one".  CIRPasses::LoopWays gives the way
	round a loop and the way out of a block that branches one way each: LessLoopTests and CanRotate had the
	same twelve lines for it.

	Not as the stage was written:
	- LoopGuarded and GuardedBy are still two functions.  The plan had one with its reach a parameter; they
	  differ in more than reach.  LoopGuarded looks up the dominators for any branch that guards the loop;
	  GuardedBy looks only at the branch the loop is entered from, past its preheaders, and takes two constants
	  where there is none, so that an idiom's own check in front of a loop is not matched again.  They share
	  the edge now, which was what each had written out.
	- There is no "loop test" record.  What the sites share is the edge (with the block the loop goes round
	  to as its end) and LoopWays; a record of both would have had two users.
	- Left as they were: NarrowCounter and ReplaceLoopCounters, which want only "round on true" of a branch
	  they go on to read in their own way, and ReplaceStrchr, whose two tests are read together.

Stage 6 (2026-11-21): a loop's counter is matched in one place.  Same code: the 4,201 listings are the
baseline's.  TestCppCompilerLib passes (271,441).

	MatchCounter was the counter passes' and is CIRPasses', so every group has it (the loop passes reached
	through the context for it).  It takes a ptradd for a step when asked to (IR_COUNTER_POINTER), as it took a
	sub when asked.  What a pass wants beyond "a phi of the head, a start from outside, itself plus a constant
	from inside" it asks of what it is given: that the step is 1, or that it comes round from the latch.

	What read the phi for itself and now asks: ReduceStrength (25 lines: the same phi, found by its entering
	block); MatchIdiomStep (stepped by 1 from the latch, agreeing with the next value it was handed);
	MatchIdiomAddress's pointer phi (a ptradd of lliBytes from the latch); MatchLinear (an add or a ptradd).
	With NarrowCounter, ReplaceLoopCounters, ReduceDivisions and ReplaceExitValues, which asked already, that
	is eight.

	Not as the stage was written:
	- It is the matcher that is shared, not an analysis the loops keep.  A kept list of each loop's counters
	  would have to be found again whenever a pass changes a loop, and no pass asks twice of the same loop
	  between changes; a matcher asked of a phi costs what the reading by hand cost.
	- There is no helper for "the value after n times round": the three places that work it out (ReplaceExit
	  Values, the idioms' count, FoundAt) each build different instructions from it.
	- Left as they were: ReplaceLoopCounters' second counter, which is found beside the first by rules of its
	  own (the same entering block, stepped in the testing block), and ReplaceStrchr's.

Stage 7 (2026-11-22): a loop's set-up is written once.  Same code: the 4,201 listings are the baseline's.
TestCppCompilerLib passes.

	CIRLoopPasses::Preheader(uiLoop) gives the loop's preheader and makes one if it has none.  The three
	forms of asking are it now: "if it is NULL, AddPreheader" (ReduceMultiplies, ReplaceExitValues,
	DeleteDeadLoops), "if the entering block's jump isn't a jump, AddPreheader" (ReduceDivisions,
	ReduceStrength), and the five idioms, which added one whether the loop had one or not.  The idioms now
	put their call in the block that was there: the listings say the block the merge passes left was the
	same.

	CIRPasses::SimpleLoop is "one way in and one way round" (the head, the entering block, the latch), which
	ReduceDivisions and ReduceStrength each opened with.  CIRPasses::AddCounterPhi adds a stepped phi (its
	start from the entering block, its step from the latch), which was three calls in three places.  The
	counter's record knows its phi (SIRLoopCounter::sPhi), so CounterUnwrapped takes the record (four
	parameters, from seven), and reads the head's two ways with stage 5's LoopWays.

	Not as the stage was written:
	- There is no one walk "for each simple loop and each of its counters" that the three Reduce passes
	  share.  ReduceMultiplies does not go by counters at all (it follows a web of phis and adds of any
	  loop with a preheader), and the other two want different things of the counter before they look at
	  the loop's blocks (a step that is positive and never wraps; any step, 16 bit or 32).  What they did
	  share is the opening and the phi, which are the two helpers.
	- Both still look through every block of the function for those in the loop, as finding 65 says.  The
	  loop's own list of blocks is in another order, and the order is the order the new instructions are
	  made in: changing it is not "same code", and nothing measured says it would be worth a stage.

	The check count is not a constant: RunParallel.py splits a test file into as many processes as its last
	run's time says, and a file run in two parts counts its 12 set-up checks twice (271,429 to 271,447 over
	this stage's runs, none failing).

Stage 8 (2026-11-22): blocks are copied by one copier.  Same code: the 4,201 listings are the baseline's.
TestCppCompilerLib passes.

	CIRBlockCopier (IRBlockCopier.h) copies a block's phis, instructions and jump, each value and block they
	name taken through what its owner says it is in the copy (CopyValue, CopyOf).  One switch rebuilds a
	jump.  What the owner may say more is what an instruction's operands, a return and a throw become.

	- The inliner is a copier.  Its Map is CopyValue; a parameter's address and another unit's source are
	  its CopyOperands; its returns and throws, which go on to the code after the call, are its CopyReturn
	  and CopyThrow.  Its CopyBlock (70 lines) is gone.
	- CIRMappedCopier copies some of a function's blocks into the same function: a map of temporaries and
	  the blocks with their copies.  UnswitchLoops copies its loop with one (its own 45 lines of phis,
	  instructions and a switch are a call), and RotateLoops copies the head with two (CopyHead gives the
	  results their temporaries, then asks for the instructions and the jump).  The two functions the loop
	  passes kept for the same maps (IROptimiserMapped, IROptimiserCopyOf) are the copier's Value and Block.
	- CIRFunction::CopyBody copies with every value itself and a block the one of its index.

	Preheader (stage 7) also makes the merged preheader of a loop several blocks enter, which RotateLoops
	and UnswitchLoops each asked for in a fourth form.

	The inliner asks through virtual functions now.  Its time, TestSupportLib65's project compiled a unit
	at a time (milliseconds, 65C64 and W65C816): 7,090 and 12,614 before, 7,214 and 12,709 after; phases
	this stage did not touch moved as much between the two runs (parse 24,360 to 24,463; code passes 26,067
	to 25,809), and the whole compile was 98 and 126 seconds before, 99 and 126 after.

	Not the same as before, where nothing reaches: a block with no jump was copied as unreachable by the
	inliner and the unswitcher and is copied with no jump now (the verifier takes neither); CopyBody copied
	a jump's fields as they stood and now sets them as the jump's kind says.
