Reshaping the 65C64 back end toward the W65C816's
==================================================

The 65C64 back end (CIR65Backend) and the W65C816 back end (CIR816Backend) share almost no
code line for line, but they do the same jobs: the duplication is in behaviour.  The 65C64
one grew as one 5,346 line file whose stages talk through member state; the W65C816 one is
split by concern (IR816Places, Instructions, Flow, Frames, Runtime, Lines, Peephole,
DeadStores).  The user's ruling (2026-11-05): the 65C64 back end is to be shaped toward the
W65C816's.  Written 2026-11-05.

The text passes are the one place the W65C816's shape isn't clearly the better one: the
65C64's decoded CIR65Code with its label table is arguably tidier than static functions over
the raw text.  Both follow what A, X and Y hold (CIR65Peephole's values, SIR816Held) and both
thread jumps.


What belongs in shared code
---------------------------

- Loop rotation.  CIR65Backend::RotateLoops does what CIROptimiser::RotateLoops does for both
  targets.  OrderBlocks doesn't depend on the target, and the W65C816 has nothing like it.
- Use counts.  CIR816Backend::FoldPointers (IR816Places.cpp) counts uses by hand: that is
  CIRFunction::CountUses, which the 65C64 already calls.
- Liveness.  CIR816Backend::PackTemporaries runs its own bit set liveness and builds its own
  ranges: CIRLiveness (ComputeSets, BuildRanges) does that, and the 65C64 uses it.  The
  W65C816's differ (folded bases, an argument used where its call pushes it, phis written on
  the way out), so CIRLiveness would need hooks for those, not a straight swap.
- Loop weights.  "8 times more per loop" is CIRLiveness::LoopWeight (depth capped at 5) and
  again inline in CIR816Backend::AllocateX (capped at 4).


Steps
-----

1. Split IR65Backend.cpp into files as the W65C816's is split, with an IR65BackendInternal.h
   for what the files share.  Mechanical: the code written is the same.
2. The frame's members into one SIR65Frame, as SIR816Frame.  The code written is the same.
3. Keeping values in A (msInA, msAvailable, msDeferred, mpsWritten) decided up front, as
   CanFuse does, instead of state carried from one instruction to the next.  The heart of the
   tangle.  Changes the code written: re-measure cycles.
4. OrderBlocks and the IR rewrites that don't depend on the target into IR passes; drop
   RotateLoops from the back end (CIROptimiser's).  The code written should be the same.
5. Call split into pushing the arguments, loading registers, the call and the clean up.
   May change the code written: re-measure cycles.
6. The shared code above (use counts, liveness hooks, loop weights) for the W65C816.
